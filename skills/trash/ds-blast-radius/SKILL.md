# ds-blast-radius

列出调用方很容易；真正要找的是文本搜索看不见的破坏，并用一次真实运行（而非论证）证明安全。

## 步骤

1. 读改动：增删改了哪些符号，改完出现哪些 diff 没写出的新行为。
2. 锁定这次改动"安全"所依赖的一两个关键事实（如"这里只删过期缓存项"）。风险大半由此决定，力气花在这里。
3. 去看搜索停下的地方：按钉住的版本读被调库的源码；看时序（异步顺序、teardown、重试）；跟数据走出去（API 响应、数据库列、文件格式、配置、跨语言共享的数据）。
4. 给每个关键事实标证据等级：
   1. 你说它是这样（单独看等于没有）
   2. 指到真实文件和行号
   3. 追了失败路径，证明到不了
   4. 跑了脚本或测试，错了会响
   5. 在跑起来的应用里复现
5. 便宜就把每个关键事实推到 4 级：写个小脚本调那个函数。
6. 报告：关键事实、各自等级与命令输出、真发现的破坏、没能证明的部分。

## 什么时候停

- 每个关键事实到 4 级以上，或说清了为什么到不了，报告写完。
- 或已找到一个真实破坏：带复现步骤，停。

## 规则

- 证明要有输出。
- 本 skill 只评估；要修交回正常流程。
