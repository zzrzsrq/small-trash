# 电纸书背诵材料生成

把思维导图式讲义 / 模板 / XMind / 多页 Word 重排成适合电纸书（汉王 N10 等 10 寸黑白屏）通读背诵的 EPUB 或大字 PDF。

## N10 硬参数（直接抄）

屏幕：10.3 英寸，1872×1404 像素，227 PPI，黑白（16 级灰）。按 1pt = 227/72 px 换算：

| 项 | 值 | 说明 |
|---|---|---|
| 页面尺寸 | **445 × 594 pt** | 竖屏；横屏 594×445 |
| 页边距 | **上 36 / 下 42 / 左右 40 pt** | 下边距留大点，方便做笔记 |
| 版心 | 365 × 516 pt | 445−80 宽，594−78 高 |
| 正文字号 | **13–15 pt** | 小于 12pt 看不清，大于 16pt 一页放不下 |
| 行距 | **1.7–1.9 倍**（约 24–27pt） | 电纸书需要比纸书更疏 |
| 标题字号 | 一级 20–22pt，二级 16–18pt | |
| 每页正文字数 | **≤ 420 字** | 按 15pt/27pt 行距、365pt 宽算 |
| 配图 DPI | **227 DPI**（与屏幕一致） | 低于此会模糊，高于此纯浪费 |
| 配图最大宽度 | **≤ 365 pt** | 超过就被缩放，细节反而丢失 |
| 图注字号 | 10–11 pt | |

校验公式（写完自己验一遍）：

```
可用高度 = 594 − 36 − 42 = 516 pt
可容行数 = 516 ÷ (字号 × 行距)     例：15pt × 1.8 = 27pt → 19 行
每行字数 ≈ 365 ÷ 字号               例：365 ÷ 15 ≈ 24 字
每页字数 ≈ 19 × 24 ≈ 456 字        留余量取 420
```

横屏：宽 594 − 80 = 514pt，可容纳更多字数，但每行过长影响阅读，用双栏（每栏 245pt）。

## 效率纪律（动笔前先读，省返工省 token）

留存方法的判据：**有效 且 省，两条同时满足**。结果对但要先做错一版再回头改（整段标黄再往回缩、重画表格发现线穿字再改裁图），既费时又费 token，不算好方法。反过来，纯为省步骤牺牲正确性（不放大验收、跳过对齐）也不行。最省的路径是第一次就照用户要求做对——返工最贵。

用户的要求逐条抄成 checklist，一次做到位。

**开工前 60 秒对齐（不逐条问，一次看清）**
- 用户给了参考图 → 照图精确复刻：标黄范围、分段、段首缩进、表格位置都从图里读。
- 没给图 → 一次问清这 7 项：页数（一页/多页）、字号容忍度、字体、段首缩进、表格形式（重画/裁图）、高亮谁标、品牌水印去除范围。
- 用户说过的每条要求写进 checklist，交付前逐项打勾。

**排版规范参考（中文公文/论文通则，非用户个人偏好）**
重排中文文档照这套通则走，凭手感容易出错：
- 正文：首行缩进 2 个汉字符、两端对齐、行距约 1.5 倍或固定 20 磅；段间不空行、靠首行缩进分段（Word 中文正文习惯）。
- 标题分级：一级最大、逐级递减（论文常用三号/小三/四号），字体宋体或仿宋，标题可加粗、正文不加粗。
- 正文用宋体/仿宋，字号以内容量与载体定（N10 见硬参数表）；强调优先用标黄，加粗在电纸书上易糊。
- 表格：能沿用原件就裁成图片插入（保真、省事），只有原件无表格时才重绘。
- 依据：GB/T 9704《党政机关公文格式》与通行学位论文格式规范（如[北大研究生写作指南](https://www.chem.pku.edu.cn/page/gaofenzi/docs/20201115160553622376.pdf)：小四号、宋体、首行缩进 2 字符、两端对齐、固定行距 20 磅；[上外学位论文规范](https://graduate.shisu.edu.cn/_upload/article/files/d9/c2/e87f444e46b483a90d76f53c9523/91fe814e-e45f-4e1a-89dc-5130dfc2f1a1.pdf)：标题分级三号/小三/四号、粗体）。N10 参数与通则冲突时，以顶部 N10 硬参数为准。

**一次成型**
- 高亮：从参考图读出准确边界 → `text.find(sub)` 定位 → 逐字符画黄底 + 画字。整段用 `stringWidth` 画一个矩形会错位（尤其跨行）。
- 表格：从去水印版裁图，一次裁对（上不带说明文字、下不截末行）；重画表格的线永远和字对不齐。
- 分段：照图一次性写进内容模型。

**交付前自检（自己做）**
1. 放大 300dpi 核对高亮边界——低分辨率缩略图会骗人，看着像标多了其实没有。
2. `get_text()` 查品牌词计数为 0、正文不缺字；渲染整页看段首缩进、表格、页数。
3. 同名覆盖后换文件名或提醒重开——用户看到缓存旧版会以为你没改。

## 先决策

1. **目标确认**：通读背诵 → 线性文本为主；快速查阅 → 保留图 + 切块。
2. **输出格式**：需要调字号/滚动 → EPUB；需要固定版式做笔记 → 大字 PDF。
3. **取舍问清**：内容塞不进一页时，是「缩小题目保正文一页」还是「允许正文跨页」。
4. **取舍落地前先只读检查**：文件是否含文本层、图片挂在哪、每篇字数/图片尺寸。

## 通用流程

1. **提取**：PDF 用 pymupdf；docx 用 python-docx（只读；`python-docx` 只装在 DSH 内置 python，写 Office 文件仍走 Univer）；XMind 是 zip，读 `content.json` 树 + `resources/` 内嵌图。
2. **线性化**：思维导图 PDF 的文本层顺序是乱的，必须渲染成图看视觉层级再重排；XMind 直接递归大纲。
3. **配图**：灰度化 + autocontrast + 轻锐化（黑白屏）；每张图逐张核对来源 PDF——曾把英语二的图配进英语一，按 xref 顺序想当然会出错。
4. **生成**：
   - EPUB：标准 zip（mimetype 首条目 STORED），EPUB3 nav + EPUB2 ncx 双目录；按板块分章节，每板块带「本板块目录 + 使用方法」，补充内容用醒目样式并明确标注「后添加/非原模板」。
   - **目录树优先从结构化层级生成**：源 PDF 带书签/大纲时先取 `doc.get_toc()`（pymupdf）或 `outline.to_list()`（SoPDF）作目录骨架；SoMark 解析 JSON 直接用其 `catalog` 数组，保留每节点的 `children / title_level / page_num / block_idx`（`page_num` 零基，`block_idx` 是块 id 不是列表下标）。空目录是合法结果（没检测到标题层级），不编造标题。EPUB 的 nav/ncx 由这棵树生成，比逐页猜标题准得多。
   - PDF：pymupdf 直接绘制；正文用**矢量文字**（清晰、可选中、体积小、翻页流畅），题目区用紧凑图片卡片（避免虚占高度）。
5. **校验**：XML 可解析、图片引用完整、目录页码正确、逐页渲染抽查、用 `get_text()` 确认每页正文都在；高亮范围对不对放大到 300dpi 看。

### 重排已有 PDF 到 N10 的实现要点

- **逐字标黄**：`text.find(sub)` 定位字符索引 → 逐字画黄底 + 画字，黄底与字严格对齐；整段用 `stringWidth` 画一个矩形会错位（尤其跨行）。范围严格照给，边界处放大 300dpi 验收。
- **表格裁图**：从去水印版按 bbox 裁 227 DPI 图插入，上不带说明文字、下不截末行。
- **字号**：一页塞 1200 字 → 8.5pt 是物理下限，如实告知，别擅自改两页。
- **字体替代**：无仓耳今楷 → 霞鹜文楷（LXGW WenKai）。加粗用描边模拟会糊，优先标黄。

## 关键踩坑

- **Python 子进程写盘常被拒**：脚本把结果以 base64 写 stdout，PowerShell `[Convert]::FromBase64String` 落盘；诊断信息走 stderr。
- **`insert_textbox` 空间不足会静默丢整段**：溢出时返回**负数**（如 `-593`）且写入 0 字符，不报错。判据：`rem >= 0` 才算写进去了，否则降字号重试。之后必须 `get_text()` 逐页验证字数——只看返回值会被骗。
- **Times New Roman 无中文**：正文含中文括注时改用宋体/SimSun，否则渲染成 `□□□`。同类设计工具自带的英文展示字体也基本没有中文字形，中文字体一律用系统字体（宋体/思源黑体/微软雅黑）。
- **Word 浮动图片压字**：把 `wp:anchor` 转 `wp:inline`，图片独占一行居中。
- **空段是分页元凶**：Word 里空段落仍占整行；删除不含图片的空段，用 space_after 控制间距。
- **正文字号自动适配**：按可用高度循环降字号，保证每篇完整一页 + 底部留白做笔记。**不得低于 8.5pt**（物理下限见上文）；触到下限就如实告诉用户，不硬塞。
- **书籍类交付**：区分「原模板内容」和「补充内容」，补充句式必须标注来源，避免用户误以为是原资料。
- **同名文件覆盖前**：确认是用户要更新的目标文件；生成后给用户明确的删除中间产物提示。
