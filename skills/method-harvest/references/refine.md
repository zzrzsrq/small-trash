# 精修已有 skill

> 主文件：[SKILL.md](../SKILL.md)。只在「改已有 skill」时读。写法权威在 `writing-for-agents`，这里只收本 skill 特有的取舍与动作。

## 内容放哪一层

改之前给每段内容定位置，按「谁会用它、什么时候用」分三支：

| 内容性质 | 去向 |
|---|---|
| 每次运行都要用的步骤 | 正文 |
| 只有命中某分支才查的判据、例子、数据 | 兄弟文件 + 正文里一条**写明触发条件**的指针 |
| 「当时怎么发现的」——实测经过、踩坑故事、迭代来历 | 删掉，不搬家 |

指针要带触发条件（「遇到 X 时读 `Y.md`」），不是裸链。光是「内容挺有用」不足以开兄弟文件——没人会在那个分支想起来查，就只是换了个文件夹的 sediment。

## 动作

1. **先备份整个目录**，带时间戳。多个 agent 并发写之前必须有回滚点。
2. **按文件范围分工**，每个 agent 只写自己那份；共享的全局规则（环境事实、CLI 契约、展示约定）留在主文件，其余文件用指针指向它。
3. **写前先读邻近文件**，只删真正重复的内容；硬约束（本机环境事实、命令名、错误码、隐私护栏）逐条保留。
4. **写后自己反查一遍**：用 `edit-consistency-audit` 的 token 反查法，查悬空指针、规则重复、过期数字、provenance 残留。
5. **跑一次真实运行验证**：frontmatter 合法、skill 能被加载、指针目标存在、脚本能编译、能跑的转换脚本实跑一次。

基线用来定写什么，写完就完成使命——不写进交付物。
