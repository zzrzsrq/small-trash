# Skill 写法补充

> 权威在 `writing-for-agents`（写 skill 时连同 `SKILL-MECHANICS.md`）：模板、命名、description、token 预算、信息层级都在那里。本文件只收本地增量，真要动笔写 skill 时读。

## 详略跟着脆弱程度走

先观察「错一步的代价」，再定写法：

| 可观察条件 | 写法 |
|---|---|
| 多条路都行，靠判断 | 文字原则，给方向 |
| 有偏好模式，允许变体 | 带参数的模板 |
| 一步错就翻车、必须一致 | 精确步骤 + 护栏 |

窄桥给护栏和确切落脚点，开阔草地给方向和信任。细节的多少由失败代价决定，不由篇幅决定。

## 一个例子就够

选最贴近真实场景的那一种语言，写完整可运行、带注释解释「为什么」的例子。agent 擅长移植；一个好例子胜过五种语言的残篇，填空模板和编造的示例都省下。

## 用 baseline 钉死纪律型 skill

这是 method-harvest 铁律在「写」这一步的落点：先看你不在场时 agent 怎么错，再写。

1. 写 ≥3 个压力场景，每个叠加几种压力（时间 + 沉没成本 + 权威 + 疲惫）。
2. 不带 skill 跑一遍，逐字记下 agent 在哪一步偏离、当时用什么理由自洽。
3. 只针对记下的偏离写 skill——每条规则对应一个观察到的借口。
4. 带上 skill 重跑同一批场景，确认每处偏离都消失。
5. 冒出新的偏离就补一条对应规则再跑，直到这批场景打不穿。

形态按 SKILL.md「形态跟着失败走」定类；上面的压力流程只用于纪律型（禁令/规则）。技巧型验「能否套到新场景」，参考型验「能否找到并用对」。

## 交叉引用

用 `**REQUIRED SUB-SKILL**：<何时先读> <skill-name>` 标出读取时机，让指针到触发时才加载。带 `@` 前缀的引用会在写入瞬间强制加载、白烧上下文，只留给确实要常驻的那一条。
