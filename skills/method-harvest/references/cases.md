# 案例记录

> 主文件：[SKILL.md](../SKILL.md)。本文件只在「这次触发值得记下来」时读。

## 为什么记这个

这套 skill 的核心假设——「经验先记成 instinct，攒够了再升 skill」——**没有数据支撑**。它可能对，也可能是我想当然。

案例记录就是验它的数据。攒够二三十个之后能回答的问题：

- `description` 写得准不准（该触发时触发了吗）
- 三层分层是否成立（那些停在 instinct 的条目，后来真的升级了吗）
- 置信度涨跌规则合不合理（真的会有条目爬到 0.9 吗）

**没有这份数据，一切改进都是拍脑袋。**

## 只记三类

全记会变成没人读的日记。只记**有判断价值的**：

| 类型 | 什么情况 | 为什么值钱 |
|---|---|---|
| `false-negative` | **该触发没触发** | 最值钱。说明 description 漏了分支 |
| `false-positive` | **触发了但没用** | 调 description 的直接依据 |
| `surprise` | 判断对了但结果出乎意料 | 调形态 / 调门槛的依据 |

**正常触发、正常结果 → 不记。** 那是应该发生的事，记下来只增加噪音。

## 一条案例长什么样

存到 `<DSH_HOME>/cases/YYYYMMDD-HHMM-<短slug>.md`：

```markdown
---
date: 2026-11-23
kind: false-negative
---
## 当时
（一句话：在干什么，什么场景）

## 该不该触发
该。因为（具体哪一条触发条件命中了）

## 实际
没触发——我直接动手了，没想起来查账本。

## 回看
这个场景下 description 没覆盖到。补一条触发词：（具体词）
```

十几行。**写得长就没人写，没人写就白设计。**

## false-negative 怎么捕获

这条没法自动记——skill 没触发，就不会有代码跑起来写记录。

只能靠你：**发现我刚才该用却没用的那一刻，说一句「刚才该触发的」。**

我收到就补一条。这是这套记录唯一需要你参与的地方。

## 什么时候整理

攒到 10 条以上时，跑一次归并：同一类 `false-negative` 出现 3 次以上，说明 `description` 有个系统性缺口，改它。

单条案例不改任何东西——那是个案。**重复出现的才是信号**，这和 instinct 的门槛是同一个道理。

## 别做的事

- 记成流水账（"我今天用了 method-harvest，做了 X"）——那是日志，不是案例
- 每次触发都记——信息稀释，最后没人看
- 记完不改任何东西——记录的终点是改 description 或改形态，不是记录本身
